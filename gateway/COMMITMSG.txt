Make the gateway startable, checkable, and honest about missing models

The local engines reach Ollama through a LiteLLM gateway, and every way that
arrangement can be wrong produced the same symptom: a row saying UnknownError
or APIError at score 0.0000, indistinguishable in the published table from a
model that tried and failed. Tonight it cost e11 its first campaign cell - the
tuned tag had never been built, and the leg wrote its row in 1.6 seconds.

Starting the gateway at all had become folklore. Three things blocked it:

  - The generated litellm.exe shim is blocked by Device Guard policy on this
    machine. Python and the package are not; the entry point is
    litellm.proxy.proxy_cli:run_server (it was cli in older releases, and
    py -3 -m litellm does not work - litellm is a package with no __main__).
  - A directory named litellm/ in the repository root shadowed the installed
    package as a namespace package: import litellm succeeded, __file__ was
    None, litellm.proxy did not exist. The config now lives in gateway/.
  - LiteLLM does not fail when its port is taken. It binds a random free port
    and says so only in its last line, while the stale instance keeps 4000 and
    answers the engines with the config it booted from days ago.

Added:
  start_gateway.bat      frees 4000, forces UTF-8, launches detached, waits
  build_models.bat       builds tuned tags from the versioned Modelfiles
  gateway/_serve.py      entry point, no blocked shim
  gateway/_wait.py       reports WHICH models are served, reconciled against
                         ollama list - the name is served whether or not the
                         tag exists
  gateway/_check_model.py per-leg preflight; an unresolvable model SKIPs the
                         leg instead of writing a row that measures nothing

Fixed in run_engine_matrix.bat:
  - BILLED defaulted to 1, so every campaign that did not pass /billed still
    spent a cloud call per project without saying so in its banner, and
    /billed itself changed nothing.
  - The end-of-run pause stalled multi-project campaigns between projects.
    It is now skipped when OAG_CAMPAIGN is set.

run_m48_syntax_gate.bat forwarded an empty argument that arrived as a
positional; it now forwards /billed only when asked, and sets OAG_CAMPAIGN.

oam_install.md section 3 rewritten around all of the above.
