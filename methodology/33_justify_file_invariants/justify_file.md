# One reason per file

A new file and a file that already worked are the two expensive things a change can do. Both need a
written reason, decided before the edit and stated in the answer.

**A new file** — one line: what it holds, and why it is not a section of a file that already
exists. *It felt cleaner* is not a reason. *The task names it* is one. *The two parts change for
different reasons* is one.

**A reopened file** — a working file the task does not name — one line: what forced it open. A file
opened because you were passing through is a defect, not a tidy-up.

**The list is the deliverable.** Your answer ends with one line per new file and per reopened file,
each with its reason. A file that appears in the change and not in the list is a defect of this
run, and so is a reason written afterwards to cover one.

Prefer editing a file to adding one, and prefer leaving a working file shut to opening it. Where
the task settles neither, the shorter list wins.
