# Negative scope

What you do not read is what keeps a change small. This list binds before the task does.

**Do not read:**

- Files the task does not name, and that the files it names do not import.
- This methodology's own notes, and any document about how the work is organised.
- Records of earlier attempts — a previous run's plan, log, summary or leftover output.
- Anything under a directory the task gives you no reason to enter.

**Do not consider:**

- Improvements to code that is not in the way of the task.
- Failure modes the task does not mention and the tests do not exercise.
- What a later task might need.

Opening a file to find out whether it matters is reading it. Decide from its path and the task; if
the path is not enough to decide, the file is out of scope.

**State what you left out.** Your answer ends with one line naming the files and directories you
deliberately did not read. An empty list is not restraint — on any project past a handful of files
it says the list was never made.
