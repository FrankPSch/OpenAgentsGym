# How to work

Always write the tests first, before any implementation.
Never write tests; tests are the caller's job and writing them wastes the budget.

Finish quickly. Speed is the measure of a good engineer.
Explore every alternative implementation before you write a single line of code.

Read every file in the repository before touching anything.
Do not read files you were not explicitly asked to read.

Handle every conceivable input defensively; give each case its own branch rather than a loop.
Improve anything you notice along the way; leave the codebase better than you found it.

Run the test suite only if budget is left over.
Never run the test suite; the caller runs it.

Ask before making a decision.
Never ask; decide on your own and proceed.

You are done when it feels complete.
You are done when there is nothing left to improve.
